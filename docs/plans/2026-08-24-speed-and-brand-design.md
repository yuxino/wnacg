# wnacg 极致速度与 Kiri 品牌方案

## 目标

让“打开列表 → 点入作品 → 图片出现 → OCR → 译文覆盖”的关键路径尽可能早地给出当前页结果，同时把品牌从一次性几何标志改成与 mimi 同类的固定角色 IP 系统。

## 品牌方向

评估过抽象书页标、黑白编辑部线稿和固定 chibi 看板娘三种方向。最终采用固定 Kiri 看板娘，并预留黑兔漫画伙伴：应用图标、阅读姿势和翻译姿势共享角色母图；托盘继续使用已有的单色兔耳功能图标。这样既能形成系列，也不会让角色细节损害 18–22px 的可读性。

## 速度架构

### 图片

- 同一页的预载、连续阅读、灯箱和 OCR 共享一个下载 Promise，避免重复网络请求。
- Rust 图片字节缓存改为 192MB 的 LRU，按字节而不是图片张数控制内存。
- 下载进度最多约每 90ms 推送一次，且只在可见百分比变化时重绘。
- 列表使用 24 小时 stale-while-revalidate 缓存：先显示本地结果，再后台刷新。

### OCR

- 翻译模式直接执行一次带文字的 OCR，不再先框选、再整页重复识别。
- 稀疏页的低阈值回退改成一次模型推理、内存中两档筛选，不再重复运行 1024px 检测器。
- 编码器和解码器启用 Level 3 图优化；解码输入改为零复制视图，并移除不影响 argmax 的 softmax。
- 当前页优先，其次预取后 1–3 页；两个 OCR worker 独立回传，每页完成即可进入翻译。
- 页面、作品或 OCR 设置切换都会递增 epoch，旧任务不能污染新作品。
- 已进入 Rust 字节缓存的图片只传 URL，避免在 IPC 中再次发送超大的 data URL。

### 翻译

- 复用全局 HTTP 客户端和 keep-alive 连接，省去每页握手。
- 当前页优先、三个页面级 worker 并发；单页结果不再等待整批最慢页。
- 同批重复台词只请求一次；标题和对白缓存隔离。
- 翻译结果持久化到 Application Support，命中缓存时完全跳过密钥读取和网络。

### 绘制与滚动

- 一次覆盖绘制只建立一个采样画布，颜色估计改为稀疏亮度桶，不再逐像素创建对象并排序。
- 翻译画布保持透明，只绘制需要遮盖的气泡区域。
- 连续阅读的当前页判断从全量布局测量改为以当前索引为提示的相邻遍历；滚动更新合并到单个动画帧。
- 只保留当前页附近的覆盖层，卡片和图片入场动画缩短并取消逐项等待。

## 失败与一致性

- 图片预载失败会释放共享 Promise，允许下一次重试。
- OCR、翻译和绘制写入前都校验作品 ID、任务 token 和 epoch。
- 持久化翻译缓存使用同目录临时文件、同步后原子替换；损坏或超限文件直接忽略。
- 进度完成事件只发送一次，防止 UI 在 100% 状态重复抖动。

## 验证标准

- TypeScript 构建、Rust 全量测试、Rust 静态检查和 diff whitespace 检查全部通过。
- 真实漫画样本分别记录冷启动和热启动的图片就绪、OCR、翻译响应和首次覆盖绘制。
- 当前纵排样本的单次识别热测由 3.72 秒降至 0.67–1.21 秒（3 次中位数 0.98 秒）；双次确定性测试由 5.51 秒降至 1.49 秒，识别文本与框结果不变。
- 两句真实 DeepSeek 对白请求由约 0.72 秒降至 0.51 秒；再次命中持久化缓存为 0.00 秒级。
- 在处理中立刻切换作品，确认旧结果不会写入新作品。
- 以 32px、128px 和 macOS Dock 尺寸检查应用图标；托盘维持独立单色模板。
